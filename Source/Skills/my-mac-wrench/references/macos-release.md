# macOS release decisions

Read only when distribution, updater, signing, notarization, installer, or remote release work is in scope. Recheck current vendor documentation for the actual toolchain and channel; these links identify authoritative starting points, not fixed policy.

- **Channel and identity:** Decide Mac App Store versus outside-store distribution from product needs and user policy. For outside-store delivery, check [Apple Developer ID](https://developer.apple.com/developer-id/) and [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution.md). Use appropriate Developer ID signing, hardened runtime/entitlements, notarization and ticket handling; inspect the built artifact and test Gatekeeper installation on a clean target where possible. Keep signing credentials out of source and logs.
- **Launch/login helpers:** If the app needs a login item or helper, verify API and target OS support in [Apple SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice). Test enable/disable, upgrades, and user-visible system settings. Do not assume private or deprecated mechanisms are acceptable to the chosen distribution channel.
- **Updates:** Use Sparkle only if the product's distribution approach calls for it. [Sparkle publishing](https://sparkle-project.org/documentation/publishing/) requires signed update archives and warns that archiving must preserve framework symlinks. Check machine-readable `CFBundleVersion` against `sparkle:version` in the generated feed, plus URL, signature, size, release notes, and update behavior. For sandboxed apps or custom signing, follow [Sparkle sandboxing](https://sparkle-project.org/documentation/sandboxing/); nested helper signing differs by integration and archive/export method.
- **Packages and Homebrew:** Choose `.app` archive, DMG, or PKG based on installation behavior. If publishing a cask, use the current [Homebrew Cask Cookbook](https://docs.brew.sh/Cask-Cookbook), including artifact, version, checksum, URL, architecture/OS constraints, and uninstall behavior. Verify that the cask installs the actual released artifact.
- **Remote builds:** When a remote macOS runner performs signing or release, pin provenance to the approved commit/tag, use least-privilege tokens and protected secrets, and inspect checks and downloaded artifacts. Follow [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use) when Actions is the platform. Confirm release, updater feed, and installer all refer to the same version and bytes before calling the product shipped.
